# Vibe Coding 省額度心法

這份指南只講可複用的工作流程，不指定特定模型名稱或配額，因為這些資訊隨時會變。

---

## 原則

1. 先規劃，再實作，最後驗收。
2. 高成本模型只做「決策、架構與審查」，不要拿高成本模型逐行寫重複代碼。
3. 低成本或免費模型做「照清單搬磚、補測試、整理格式」。
4. 每完成一段工作就清空上下文或開新對話，避免歷史 token 滾雪球。
5. 修改大型檔案時要求 AI 只輸出 diff，不要整檔複寫。

---

## 實際工作順序

```text
規劃（釐清需求、拆任務） -> 實作（逐項建立檔案） -> 執行測試 -> 審查與修正
```

重點不是「哪個模型最強」，而是「哪個模型適合目前這一步，以及它當下還有沒有免費額度」。

---

## 選擇後端時

請到官方頁面確認：

- 當前是否還有免費額度。
- 該模型的 context 長度。
- 是否支援 function calling / tool use。
- 免費層資料訓練政策。

官方入口整理在 [`free-ai-tiers.md`](free-ai-tiers.md)。

---

## 多層備援

可以同時準備多個後端，例如官方免費層、平價 API 與本機代理。當一個額度用盡或回 `429` 時，切到另一個。

本專案的 `scripts/server-multikey.js` 只負責本機代理與金鑰輪換，不保證能突破上游總量限制。
